## Real provider checks

The existing native synthetic-corpus diagnostic exercised the hosted Flux WebSocket endpoint with one decoding pass and no paid vocabulary hints. It used the same 28 synthetic fixtures as the earlier ElevenLabs investigation: 12 clean, eight mild rumble, four heavy rumble and four competing-speaker mixtures. These checks are not a human accent benchmark.

The original, tightly trimmed fixture run completed 27 clips. One initial connection timed out; a separate retry completed the remaining clean clips. The heavy-rumble fast “oat milk” clip twice returned no final transcript within the five-second bound. Failed requests did not produce invented text or switch recognition providers.

Recognition was mixed. Addition and multiplication stayed distinct. Clean “oat milk” was correct. A competing-speaker version was badly misheard, and one noisy negative changed “save” to “say”; the negative still cannot approve a memory. No general accuracy advantage over ElevenLabs is established.

The short clean “Yes, save that” fixture repeatedly lost “that”. This needed a separate check before blaming recognition: the original synthetic clip has only a short quiet tail. Sending identical speech with another 240 ms of zero PCM returned the complete phrase; 500 ms did too. This points to decoder lookahead at external finalisation, rather than omitted client bytes. Each audio send is awaited before `ForceEndTurn`.

The app already sends real microphone silence to recognition while waiting for its 1.2-second endpoint. `Worker::frame` streams each frame before evaluating the end condition, then flushes the last packet before the end event. The capture regression test checks that streamed PCM and the captured WAV have the same length. No delay or padding was added to normal use. A separate run with 1.2 seconds of synthetic endpoint silence completed 27 of 28 clips. The short approval was complete, but the competing-speaker fast phrase was still wrong and the heavy-rumble fast phrase still timed out. These results remain distinct from the original trimmed run. Keeping the existing memory read-back requirement is necessary; switching recognisers does not eliminate mishearing.

## Acoustic pipeline check

A known wake-phrase sample played through the Mac speaker activated the real microphone path. Deepgram produced “Please calculate five plus seven.” The companion chat recorded Terra/Medium and replied “Five plus seven is twelve.” The app entered listening, thinking and metered speaking, then resumed wake listening. Streaming reported 13 partial events, one final segment and no error.

In this single acoustic run, capture ended at `1793221616416` ms and the speaking animation began at `1793221621030` ms: about 4.6 seconds from endpoint to playback state. The model turn itself completed in about 2.6 seconds. The test operator left a gap between wake playback and request playback, so total capture time is not a measure of human conversational latency. This is a synthetic speaker-to-microphone check, not confirmation that a person heard a clean reply.

A second acoustic compiler request produced the correct transcript and began streamed speech. Escape stopped playback, the runtime recorded `turn_aborted`, and the app returned to idle/listening about 0.3 seconds after that abort. No missing-turn-ID error appeared. A wake activation followed by no request returned to listening without another model turn.

A separate 24.14-second synthetic stream crossed the old 20-second segmentation boundary and returned one complete final transcript, including the final multiplication question. Total diagnostic time was 25.54 seconds, including paced audio upload and connection setup. This checks the hosted streaming boundary, not a long microphone conversation. The three existing memory-confirmation tests also passed, including rejection, cancellation and stale-worker protection; those are component tests, not acoustic memory acceptance.

The user then confirmed the real spoken wake-and-maths check: the correct reply was audible and activation felt prompt. Acoustic memory read-back still needs its remaining acceptance check. The corpus limitations above remain; this is not a general accuracy guarantee.
