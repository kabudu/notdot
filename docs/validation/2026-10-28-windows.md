# Windows acceptance — 28 October 2026

Acceptance is in progress. The fresh candidate installed successfully; the full Windows voice workflow has not passed yet.

## Runtime setup

The Windows App connection reaches the user's x64 Windows laptop. The existing Windows Store Codex installation is present, but launching its protected bundled CLI from PowerShell returns Access Denied. Its permissions were left intact.

OpenAI's official standalone installer installed Codex CLI 0.165.0. Windows PowerShell 5.1 could not evaluate the installer's `RuntimeInformation.OSArchitecture` property. After verifying `PROCESSOR_ARCHITECTURE` was AMD64, only that architecture expression was replaced with `X64` in the downloaded script in memory. The installer retained its download and integrity checks. No credentials were exported.

The initial browser sign-in did not establish a CLI session: `codex login status` reported `Not logged in`. The user completed a fresh device authorisation while PowerShell remained running. It printed `Successfully logged in`, and a separate `codex login status` confirmed `Logged in using ChatGPT`. Browser ChatGPT sign-in alone does not prove the bridge is authenticated.

## Candidate

Source: `7be5835`, release profile, `custom-protocol`, Windows x64, bundled local wake models. The unsigned NSIS installer is 44.76 MiB. It has not been uploaded as a public release.

SHA-256:

```text
213a3b824fb902c9d0a4dc5fe7bbefff58ed6203934c76bcb9f763b711f6de54
```

The Linux-hosted cross-build used Rust 1.97.1, cargo-xwin 0.23.1 and LLVM 20, followed by Tauri NSIS bundling on macOS. An SDK cache symlink corrected `PathCch.lib` casing on the case-sensitive Linux filesystem. No library was substituted. Build logs and the installer remain under ignored `.local/windows-e2e`.

The build exposed incompatible C runtime choices in sherpa-onnx and whisper.cpp. The committed Cargo configuration selects the static runtime consistently; Tauri's separate partial-runtime shim is disabled. The resulting executable imports Windows system libraries without a separate Visual C++ runtime DLL dependency. Linker warnings concern missing Microsoft SDK debug symbols, not missing executable symbols.

The standalone runtime discovery regression test, formatting and warnings-as-errors Clippy checks passed. Desktop launches now check the official per-user Codex native executable location before relying on PATH. These checks do not establish runtime compatibility or voice acceptance.
