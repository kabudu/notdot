# Linux validation — 29 October 2026

Linux desktop and hardware voice acceptance remain incomplete. These checks use an isolated Debian 12 virtual desktop in Docker on the Mac; no host microphone, speakers, login files or real voice keys are mounted. Windows owns the host audio test slot. Linux audio tests use only a generated tone and a null sink inside the container.

## Environment and boundaries

- Current branch `codex/rust-orb-bridge`, based on `5e4c3d8` plus the changes in this report; final checks must match the final revision.
- Rust 1.97.1, GTK 3.24.38 and WebKitGTK 2.50.6. The x86-64 process runs under Docker Desktop's Rosetta emulation, not physical Linux x64 hardware.
- The initial Linux release build completed in 6m51s, limited to three CPUs, two Cargo jobs and 5 GiB RAM. Approximately 2.8 GiB was observed during compilation. This is build evidence, not application performance evidence.
- A separate disposable, unprivileged `qa` desktop runs Xvfb/Openbox, D-Bus Secret Service and PulseAudio. Its noVNC endpoint binds only to Mac loopback, `127.0.0.1:6091`. It is limited to two CPUs and 3 GiB RAM. WebKit started without disabling its sandbox.
- The installed Debian package contains the actual release app and bundled wake resources. No fake Codex executable, account or speech provider is used to turn a disconnected app into a successful model test.

## Initial results

- Linux x64 release build, Debian packaging and installation passed. `ldd` reported no missing libraries in the configured lab. The package was 60.87 MiB before the subsequent speech-engine dependency fix. Its binary requires up to `GLIBC_2.34` and `GLIBCXX_3.4.30`; this alone does not establish compatibility with another distribution.
- The actual unprivileged app and WebKit subprocesses ran. Native GUI checks are recorded separately by the coordinating test run; a running process alone is not UI acceptance.
- Orb, voice, core and bridge offline suites passed: 14 + 17 + 25 + 7 tests, respectively; five explicitly live tests were ignored. The x64 native suite reached a Whisper fixture and Rosetta aborted with `could not find free space for allocation size 555556439000`. The whole native suite is therefore not a pass. Native ARM Linux comparison is being used to investigate this emulation boundary; no model code is changed to suppress it.
- An explicitly gated native integration test passed real CPAL → ALSA → PulseAudio capture of a generated tone from `notdot_qa_sink.monitor`, closing and reopening capture twice. It ran in 4.90s. This proves the container's native capture route, not microphone recognition, wake-word accuracy or STT/TTS/model E2E.

## Defects and fixes under verification

### Missing runtime error

There is no Codex executable in the disposable Linux home, system candidates or PATH. Under Rosetta, a minimal Rust `Command::spawn("codex")` unexpectedly returns a child; writing to its stdin fails with `BrokenPipe` and the child exits 127 with empty stderr. This explains why the app displayed a pipe error instead of its existing missing-runtime setup message. The coordinating change resolves the executable before spawning it. This does not install or authenticate a runtime.

### Local system voice dependency

With the package's declared dependencies and no recommended packages, `spd-say` existed but only the dummy output module was available; a synthetic alert timed out. Installing `speech-dispatcher-espeak-ng` made the same alert finish successfully, with nonzero PCM captured entirely in the virtual sink. The Debian dependency list now includes the speech engine explicitly; the guide explains that AppImage users need it too. Real speaker audibility is not established by null-sink PCM.

### Credential-store lifecycle

The lab uses only an unlocked, explicitly labelled `notdot-disposable-qa` collection and synthetic values. The automated Linux-only test refuses an existing provider credential and an unmarked collection. It exercises save, noninteractive read, replacement, session cache, fresh-vault persistence and removal, with cleanup.

An earlier isolated probe also observed that a locked collection denied a noninteractive read without becoming unlocked, while an already authorised session cache remained available. Its GNOME control-daemon cleanup did not unlock the relabelled collection, so that full probe failed; it is not counted as a passing lifecycle test. Only the disposable synthetic keyring was recreated. The committed lifecycle regression avoids locking an entire collection; the separate lock observation remains limited evidence.

## Final regression and package results

- Native ARM Linux comparison: **107 passed, 13 explicitly ignored** across the full default workspace suite. All bundled Whisper/keyword fixtures passed; the native app suite took 20.18s. The first GCC 12 build failed in upstream GGML FP16 architecture detection. A diagnostic retry used its supported `GGML_NATIVE=OFF` and `GGML_CPU_ARM_ARCH=armv8.2-a+fp16` build flags; no model or product source was altered to mask the failure. This comparison is not a newly advertised ARM release target, and its VM timing is not end-to-end voice latency.
- Linux x64 under Rosetta: **101 passed**, with six model fixtures deliberately excluded after the recorded emulation crash and 13 explicitly ignored tests. The missing-runtime regression passed in the eight-test bridge suite. This filtered run does not replace acceptance of the six fixtures on Linux x64 hardware.
- Two additional explicitly gated x64 OS checks passed: real Secret Service save/read/cache/fresh-vault/remove in 0.18s, and native virtual capture/reopen in 4.64s. The synthetic key was removed and the store was checked afterwards.
- Native ARM Linux all-target Clippy passed with warnings denied for the application. Existing vendored GLib dependency warnings remain visible. Formatting and diff whitespace checks passed.
- The coordinating CUA run verified that Settings fits, scrolls, collapses and drags. Name `Linux QA` and the purple theme (hue 279) persisted through Save, reopening Settings and restarting the final installed app. The final app displays the helpful missing-runtime setup message instead of a raw pipe error.
- Enabling **Start notdot when I sign in** and saving through the Linux GUI created `~/.config/autostart/notdot.desktop` with `Exec=/usr/bin/notdot --startup`, `Terminal=false` and `StartupNotify=false`; saved settings changed to `startup=login`. Switching it off and saving through the GUI removed that file and restored `startup=manual`, while retaining the name/theme. Registration and removal are verified; an actual desktop sign-in launch has not been tested.
- The final Debian package, including the explicit speech-engine dependency and missing-runtime fix, was installed successfully. Its binary SHA-256 is `78b951dacf2861aba407add7cbfa0db81655f258f9f031689a8c75c4d2bfe4f2`. The profile was preserved when the disposable app restarted.
- A fresh executable was used for each package format to avoid Tauri reusing a previous format's bundle marker. The AppImage correctly received the `appimage` stamp without the earlier already-patched warning. It is **206,989,816 bytes**, below the updater's 256 MB bound. Its SquashFS fully extracted, its app binary matched the staged payload, all shipped model/tokeniser/VAD checksums passed, and the libav, mpg123, playback and audio-conversion GStreamer plugins are present. The Debian model checksums also passed.
- The AppImage's static-PIE launcher cannot execute under this Mac's Rosetta: even `--appimage-offset` falls back to an ELF/shell execution error. SquashFS inspection/extraction proves package integrity, not a native AppImage launch, update or restart.

## Remaining gates

A genuine Linux runtime/account, known speech, audible reply, real wake activation, cancellation during model work/playback, codec/device switching, actual desktop-sign-in activation and installed AppImage update/restart still need acceptance. No public release, CI enablement or demo recording occurs in this test run.

Logs and generated artifacts are ignored under `.local/linux-e2e/`; container/cache names begin with `notdot-linux-`.

The disposable lab keyring uses a public fixture password. Never enter real provider keys into this lab. After the coordinating GUI checks, the lab container was stopped (not removed), and a connection check confirmed that loopback port6091 no longer listens. Its disposable profile and local artifacts are preserved for further synthetic testing.
