# Linux validation — 29 October 2026

Linux desktop and hardware voice acceptance remain incomplete. Initial checks used an isolated Debian 12 desktop in Docker on the Mac; a later full ARM Linux VM is documented below. Neither environment imports host login files or real voice keys. Windows owns the host audio test slot. Linux audio tests use only a generated tone and a null sink inside the container.

## Environment and boundaries

- Current branch `codex/rust-orb-bridge`, based on `5e4c3d8` plus the changes in this report; final checks must match the final revision.
- Rust 1.97.1, GTK 3.24.38 and WebKitGTK 2.50.6. The x86-64 process runs under Docker Desktop's Rosetta emulation, not physical Linux x64 hardware.
- The initial Linux release build completed in 6m51s, limited to three CPUs, two Cargo jobs and 5 GiB RAM. Approximately 2.8 GiB was observed during compilation. This is build evidence, not application performance evidence.
- A separate disposable, unprivileged `qa` desktop runs Xvfb/Openbox, D-Bus Secret Service and PulseAudio. Its noVNC endpoint binds only to Mac loopback, `127.0.0.1:6091`. It is limited to two CPUs and 3 GiB RAM. WebKit started without disabling its sandbox.
- The installed Debian package contains the actual release app and bundled wake resources. No fake Codex executable, account or speech provider is used to turn a disconnected app into a successful model test.

## Initial results

- Linux x64 release build, Debian packaging and installation passed. `ldd` reported no missing libraries in the configured lab. The package was 60.87 MiB before the subsequent speech-engine dependency fix. Its binary requires up to `GLIBC_2.34` and `GLIBCXX_3.4.30`; this alone does not establish compatibility with another distribution.
- The actual unprivileged app and WebKit subprocesses ran. Native GUI checks are recorded separately by the coordinating test run; a running process alone is not UI acceptance.
- Orb, voice, core and bridge offline suites passed: 14 + 17 + 25 + 7 tests, respectively; five explicitly live tests were ignored. The x64 native suite reached a Whisper fixture and Rosetta aborted with `could not find free space for allocation size 555556439000`. The whole native suite is therefore not a pass. Native ARM Linux comparison is being used to investigate this emulation boundary; no model code is changed to suppress it.
- An explicitly gated native integration test passed real CPAL → ALSA → PulseAudio capture of a generated tone from `notdot_qa_sink.monitor`, closing and reopening capture twice. It ran in 4.90s. This proves the container's native capture route, not microphone recognition, wake-word accuracy or STT/TTS/model E2E.

## Defects and fixes under verification

### Missing runtime error

There is no Codex executable in the disposable Linux home, system candidates or PATH. Under Rosetta, a minimal Rust `Command::spawn("codex")` unexpectedly returns a child; writing to its stdin fails with `BrokenPipe` and the child exits 127 with empty stderr. This explains why the app displayed a pipe error instead of its existing missing-runtime setup message. The coordinating change resolves the executable before spawning it. This does not install or authenticate a runtime.

### Local system voice dependency

With the package's declared dependencies and no recommended packages, `spd-say` existed but only the dummy output module was available; a synthetic alert timed out. Installing `speech-dispatcher-espeak-ng` made the same alert finish successfully, with nonzero PCM captured entirely in the virtual sink. The Debian dependency list now includes the speech engine explicitly; the guide explains that AppImage users need it too. Real speaker audibility is not established by null-sink PCM.

### Credential-store lifecycle

The lab uses only an unlocked, explicitly labelled `notdot-disposable-qa` collection and synthetic values. The automated Linux-only test refuses an existing provider credential and an unmarked collection. It exercises save, noninteractive read, replacement, session cache, fresh-vault persistence and removal, with cleanup.

An earlier isolated probe also observed that a locked collection denied a noninteractive read without becoming unlocked, while an already authorised session cache remained available. Its GNOME control-daemon cleanup did not unlock the relabelled collection, so that full probe failed; it is not counted as a passing lifecycle test. Only the disposable synthetic keyring was recreated. The committed lifecycle regression avoids locking an entire collection; the separate lock observation remains limited evidence.
